# Spanbox UI Polish Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the seeded ink-and-rose visual polish across every spanbox web surface without changing routes, CSP, template safety, or existing behavior.

**Architecture:** Keep the current `html/template` + htmx + uPlot stack. Centralize the visual world in `internal/web/static/app.css`, read those tokens from `app.js` for charts, make only narrow template changes for semantics and kind markers, and adjust authentication only so the login page can load the same self-hosted assets.

**Tech Stack:** Go `html/template`, embedded static assets, CSS, vanilla JavaScript, htmx, vendored uPlot, agent-browser.
